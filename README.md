# 🚀 PINA Tutorials

Step-by-step tutorials for [**PINA**](https://github.com/PINA-org/PINA), the
Physics-Informed Neural Architectures library.

This repository holds the tutorial sources that were formerly part of the main
PINA repository. Every tutorial is a self-contained Jupyter notebook that runs
top-to-bottom, on your laptop or in the browser.

> **Rendered versions** of all tutorials are published in the
> [PINA Tutorials website](https://PINA-org.github.io/PINA-Tutorials/),
> where they are indexed and searchable.

## Quick start

The fastest way to try a tutorial is **Open in Colab** — every notebook has a
Colab badge at the top, and needs nothing but a browser.

To run one locally instead:

```bash
git clone https://github.com/PINA-org/PINA-tutorials.git
cd PINA-Tutorials
pip install "pina-mathlab[tutorial]"
```

Then open, for example, `tutorial17/tutorial.ipynb` in Jupyter. Notebooks that
ship a `data/` folder read it from disk; notebooks that need a dataset they do
not carry (Darcy flow, Kuramoto–Sivashinsky, …) download it on first run when
executed in Colab.

## Repository layout

```
tutorial<N>/
    tutorial.ipynb   # the source; this is the only file you should edit
    tutorial.py      # nbconvert export, regenerated by CI from the notebook
    data/            # dataset, when the tutorial ships one
static/              # images embedded by the notebooks
```

Notebook numbers are permanent identifiers: `tutorial17/tutorial.html` is the
URL in the documentation and will not be reused for different content.

## Writing a tutorial

Please read **[CONTRIBUTING.md](CONTRIBUTING.md)** first. It defines the
required structure, the writing style, and the contribution checklist — a
tutorial PR should contain only the `.ipynb` and the `README.md` entry for it.

A **"What's Next?"** section closing every tutorial is mandatory.

## How the rendered tutorials are produced

`.github/workflows/exporter.yml` exports each changed notebook and publishes
the result:

* `tutorial<N>/tutorial.py` — a plain-Python export, committed to this
  repository through a `maintenance` pull request.
* `docs/source/tutorials/tutorial<N>/tutorial.html` — an HTML export of the
  executed notebook, included in the same pull request for the standalone
  tutorial website. Deployment is configured separately.

The exporter automatically generates Python scripts and executed HTML pages when
notebooks change on `main`. Manual runs regenerate all tutorials. Notebooks run
in their own directories to access local datasets, without saving execution
outputs to the source notebooks. If execution fails, the export stops.
